这篇文章遵循一条原则:**源码即文档**。你在编辑器里看到的这一行写的是 `**源码即文档**`,在页面上看到的就是加粗后的样子。想知道某个效果怎么写,直接看这个文件的源码即可,不必在"示例"和"效果"之间来回对照。

## 行内文本

这是普通正文。**这是加粗效果**,*这是斜体效果*,***这是加粗兼斜体***。~~这是删除线~~。

行内代码写成 `const answer = 42`,链接写成 [Nuxt 官网](https://nuxt.com),自动链接写成 <https://content.nuxt.com>。

换行有两种:段落之间空一行,得到两个独立段落;
行末打两个空格再换行,得到同一段内的软换行(上面这一行就是)。

## 标题层级

正文里能用到的标题从 `##` 开始 —— `#` 留给文章标题本身,由 frontmatter 的 `title` 承担,正文里再写一个会出现两个一级标题。

### 三级标题

大纲(页面右侧那栏)只收 h2 与 h3,层级更深的不进目录,但排版上仍有区分。

#### 四级标题

到这一级就该考虑是不是该拆成新的小节了。

## 列表

无序列表:

- 第一项
- 第二项
  - 嵌套项,缩进两个空格
  - 再来一项
- 第三项

有序列表:

1. 先做这个
2. 再做那个
3. 最后收尾

任务列表(GFM 扩展):

- [x] 已完成的事项
- [ ] 待办事项

定义型内容用嵌套段落的写法:

- **术语一**

  解释文字另起一段,与列表项之间空一行、缩进对齐。

- **术语二**

  同上。

## 引用与分隔

> 引用块用于插入他人的话或需要与正文拉开距离的段落。
>
> 它可以有多段,也可以包含 `行内代码` 与**强调**。

分隔线用三个减号:

---

分隔线之后的内容。

## 表格

表格用管道符分列,第二行的冒号控制对齐:

| 语法 | 用途 | 是否 GFM 扩展 |
| :--- | :--- | :---: |
| `**粗**` | 加粗 | 否 |
| `~~删~~` | 删除线 | 是 |
| `- [ ]` | 任务列表 | 是 |
| `[^1]` | 脚注 | 是 |

列多的宽表不会撑破正文栏 —— 它被包在一个可横向滚动的容器里,窄屏上在表格内部滑动即可:

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| `title` | `string` | 是 | — | 文章标题,同时用于页面 title 与分享卡片 |
| `description` | `string` | 是 | — | 摘要,用于列表页、meta description 与 RSS |
| `date` | `Date` | 是 | — | 发布日期,决定排序与前后篇导航的顺序 |
| `updatedDate` | `Date` | 否 | — | 更新日期,填了才会在元信息行显示 |
| `tags` | `string[]` | 否 | `[]` | 标签,不能包含斜杠,否则会破坏标签页路由 |
| `draft` | `boolean` | 否 | `false` | 为真时不进入生产构建,也不会出现在订阅源里 |

## 脚注

脚注在正文里留一个标记[^1],正文末尾自动汇总成一节。同一个脚注可以被引用多次[^1]。

[^1]: 脚注内容写在文件任意位置,渲染时会统一移到文末并自动编号。
