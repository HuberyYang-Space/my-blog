# 验证时会骗人的东西

> 改完去浏览器里看效果之前读;改完 markdown 页面却没变化时读。

共同的形状是:**你观测到的现象可能根本不是当前代码的现象**。观测工具给出的假结论比
没有结论更危险 —— 它会让人写出一整段自信但从未被走到的代码。

## markdown 编辑不会热更新

- **`@nuxt/content` 3.15.2(当前最新版)在自定义 collection 下,dev 模式改
  [`content/blog/`](../content/blog/) 下的 `*.md` 不会触发页面更新**,需要手动重启
  `pnpm dev` 才能看到最新内容。这是上游未解决的问题
  ([nuxt/content#3512](https://github.com/nuxt/content/issues/3512)),不是本项目配置错误。
- 现象具体是:Vite 能侦测到文件变化(日志打出 `Vite server hmr N files`),但内容库
  `.data/content/contents.sqlite` 不会重新写入 —— 文件改了,数据库时间戳却停在旧值,
  页面自然拿不到新内容。**日志"看起来在动"不代表内容真的更新了**,判断要看数据库或页面
  实际内容,不能只看有没有 HMR 日志。
- 已实测过的 workaround 均**无效**:升级到最新版(已是最新)、加
  `experimental: { watcher: 'chokidar' }`。项目当前不在
  [`nuxt.config.ts`](../nuxt.config.ts) 里保留这个配置项,没有理由留一段不起作用的代码。
- 目前的应对方式就是手动重启:改完 markdown,`Ctrl+C` 杀掉 `pnpm dev` 再重新跑一次。
  接受这个成本,不为它引入额外的自动重启脚本。

## 浏览器可能还在跑旧模块

改完 `.vue` 去浏览器里看效果时,**浏览器可能还在跑缓存里的旧模块**。踩过一次,代价是
连着几轮"验证通过"的结论全部作废 —— 磁盘上文件是新的、`curl` 直接问 dev server 也返回
新代码,唯独浏览器加载的还是旧的那份,`Cmd+Shift+R` 都没换掉。

- **判据要选能区分新旧的**。当时用的"验证"是在控制台里按新算式算一遍理论值,算出来当然是对的 ——
  那验证的是算式,不是页面。要么找一个只有新代码才有的可观察行为,要么直接比对浏览器实际加载的模块文本。
- **先确认版本,再开始测**。可靠的做法是从 dev server 直接取一次源码比对:
  `curl -s "http://[::1]:3000/_nuxt/@fs<仓库绝对路径>/app/components/Xxx.vue" | grep <新代码里的标识符>`。
  注意 `/_nuxt/app/components/Xxx.vue` 这种路径是 404,要走 `@fs` + 绝对路径。
- **一轮测不通就先怀疑版本,别急着改代码**。否则会去"修"一个已经修好的问题,
  甚至把对的代码改坏。

## Claude in Chrome 隔离环境里不工作的东西

不要用它们做判断依据:

- `ResizeObserver` —— 连规范要求的首次触发都没有。
- `window.dispatchEvent` 派发的事件 —— 到不了页面自己的监听器。
- `resize_window` —— 对最大化/跨屏的窗口无效,`outerWidth` 报 0。

需要验证这类行为时,改用别的可观察量,或者直接让人肉眼确认。
