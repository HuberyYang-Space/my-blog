# 协作文档布局:为什么是现在这样

2026-09-18 做的一次重构。记录动机与判据,免得下次会话把外放的内容"顺手搬回"
[`CLAUDE.md`](../CLAUDE.md)。

## 动机

重构前 `CLAUDE.md` 391 行 / 31.7 KB,每轮会话常驻。里面混了两类东西:

- **约束性**:现役禁令、跨文件的隐式契约、踩过的坑及其理由。写得成「现在要/不要做什么」。
- **叙述性**:选型对比、目录树、评估记录、一次性的实现笔记。读者有明确的
  「我现在需要它」的时刻,不必每轮常驻。

判据是**时态**:写不成「现在要/不要做什么」的句子,就该外放。

## 分工

| 目录 | 内容 | 谁读 |
| :--- | :--- | :--- |
| [`CLAUDE.md`](../CLAUDE.md) | 约束性 | 每轮常驻 |
| `.docs/` | 叙述性 | 按 [`README.md`](README.md) 索引按需读 |
| [`docs/agents/`](../docs/agents/) | skill 的运行时配置 | skill 自己读 |

**`docs/agents/` 不能并进 `.docs/`**。它的路径被 mattpocock-skills 硬编码
(`skills/engineering/code-review/SKILL.md` 等处直接按此路径读取),挪走会让
`/code-review`、`/triage` 找不到文件,且不报错 —— 只是安静地退化。

## 外放时守的两条规则

1. **理由要跟着禁令走**。不要把「不要把 X 加回来」留在 `CLAUDE.md`、把「为什么」外放:
   没有理由的禁令会被下一个会话当成疏漏"顺手改正"。所以外放是整节搬,不是把正文
   拆成"禁令留下、解释挪走"。
2. **索引行三段缺一不可**:「改 X 之前 → 读 `.docs/y.md` → 不读的后果是 Z」。
   没有触发条件就不知道何时读,没有后果就没有读的动机。
   **每次都要做的操作**(开工、提交)没有触发条件可挂,单列成「每次必读」,
   不要挂成触发式索引 —— 指针没被触发的后果是静默的。

**合并「本地开发限制」与「浏览器验证」的理由**:两者是同一件事的两个面 ——
你观测到的现象可能是假的(HMR 日志在动但数据库没更新 / 浏览器跑的是缓存里的旧模块)。
分成两份会让下一个会话只读到一半。

留在 `CLAUDE.md` 的是 MDC 组件约定、样式归属、图片约定、守门机制、注释约定、
写文章约束、视觉效果注意事项,以及目录结构的五条核心原则 —— 全是跨文件契约,
没有「改某个文件之前」这种收窄的触发条件,挂不成索引。

## 链接化范围

指向文件的文本加 Markdown 链接,但**只在每节首次出现时加**,同节内重复提到的
同一个文件保持裸 inline code。全部出现处都加会让正文被方括号和重复路径塞满,
与瘦身的目标相反。
